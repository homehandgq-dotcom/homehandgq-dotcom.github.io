# 美国餐饮业发展协会（ARDA）官方网站

American Restaurant Development Association — 官方网站与后台管理系统。

面向纽约州注册非营利性行业协会的双语（中/英）门户网站：公开门户 + 独立登录的后台管理系统，全部内容（新闻、活动、委员会、分会、领导人、合作伙伴、页面、下载资料、导航菜单、站点设置）均可在后台增删改查，不依赖硬编码；提供完整的在线入会申请与审核工作流。

## 技术架构

|层|技术选型|
|-|-|
|前端框架|Next.js 16（App Router / Turbopack）+ React 19 + TypeScript|
|样式|Tailwind CSS v4（`app/globals.css` 内 `@theme` 定义设计令牌）|
|数据库 / 认证 / 存储|Supabase（Postgres + Auth + Storage）|
|表单|React Hook Form + Zod|
|富文本编辑|Tiptap|
|图表|Recharts|
|数据导出|PapaParse（CSV）+ ExcelJS（XLSX）|
|部署目标|Vercel（应用）+ Supabase Cloud（数据库/存储）|

网站分为两大部分：

* **公开门户**：`/zh/...` 与 `/en/...` 双语路由，语言切换保留当前页面。所有展示内容（新闻、活动、委员会、分会、领导人、合作伙伴、页面正文、导航菜单、首页统计数字等）均从数据库读取，没有写死在代码里的业务内容。
* **后台管理系统**（`/admin`）：独立登录（Supabase Auth），基于角色的权限控制（RBAC，5 种角色），内容管理、会员申请审核、正式会员管理、站点设置、操作日志等模块。

## 快速开始（本地开发）

### 环境要求

* Node.js 20+
* npm（随 Node 自带）
* 一个 [Supabase](https://supabase.com) 项目（免费额度即可开始）

### 1\. 安装依赖

```bash
npm install
```

### 2\. 创建 Supabase 项目

在 [supabase.com](https://supabase.com) 新建一个项目，记录以下三项信息（Project Settings → API）：

* `Project URL`
* `anon public` key
* `service\\\\\\\_role` key（**务必保密，绝不能出现在浏览器端代码或 `NEXT\\\\\\\_PUBLIC\\\\\\\_` 前缀的变量中**）

### 3\. 配置环境变量

复制 `.env.example` 为 `.env.local`，填入上一步获取的值：

```bash
cp .env.example .env.local
```

```env
NEXT\\\\\\\_PUBLIC\\\\\\\_SUPABASE\\\\\\\_URL=https://your-project-ref.supabase.co
NEXT\\\\\\\_PUBLIC\\\\\\\_SUPABASE\\\\\\\_ANON\\\\\\\_KEY=your-anon-public-key
SUPABASE\\\\\\\_SERVICE\\\\\\\_ROLE\\\\\\\_KEY=your-service-role-key
NEXT\\\\\\\_PUBLIC\\\\\\\_SITE\\\\\\\_URL=http://localhost:3000
```

`EMAIL\\\\\\\_PROVIDER\\\\\\\_API\\\\\\\_KEY`、`CAPTCHA\\\\\\\_SECRET\\\\\\\_KEY` 等为预留扩展位，本期未强制要求配置（详见文末「项目进度总结」）。

### 4\. 执行数据库迁移

推荐使用 [Supabase CLI](https://supabase.com/docs/guides/cli)：

```bash
npm install -g supabase
supabase login
supabase link --project-ref your-project-ref
supabase db push
```

`supabase db push` 会按顺序执行 `supabase/migrations/0001\\\\\\\_...sql` 到 `0011\\\\\\\_storage\\\\\\\_buckets.sql`，建立全部数据表、行级安全策略（RLS）、辅助函数与存储桶。

也可以不用 CLI，直接在 Supabase Dashboard 的 SQL Editor 中，按文件名顺序（0001 → 0011）依次粘贴执行每个迁移文件的内容。

> 本项目在开发过程中已在本地 Postgres 16 环境完整执行过全部 11 个迁移文件与种子数据，确认可无错误顺序执行、外键与 RLS 策略生效。

### 5\. 写入种子数据（角色、初始栏目、领导人名录等）

```bash
supabase db execute --file supabase/seed.sql
```

或在 SQL Editor 中执行 `supabase/seed.sql` 全文。种子数据包含：

* 5 种角色、8 项权限及其对应关系
* 6 种会员类型、10 个行业分类
* 6 个委员会、11 个分会（地方分会 + 海外网络）
* 用户提供的完整初始领导人名录（会长、执行副会长、秘书长等，未确定人选处标注「待定 / TBA」）
* 19 条导航菜单项、25 条页面内容（关于我们 / 法律页面 / 协会服务等分组）
* 首页统计数字、首屏文案、联系方式等 6 项站点设置
* 2 条示例新闻、1 条示例活动（均为真实可编辑内容，非充数据）
* 1 条草稿状态的示例合作伙伴（`status = draft`，不会出现在前台，仅用于后台功能演示）

**没有任何虚构的政府认证、合作伙伴数量或历史成就数据被写入。** 会员数量、合作伙伴等统计项在没有真实数据前显示为 0 或「暂无」，而非编造数字。

### 6\. 本地启动

```bash
npm run dev
```

打开 http://localhost:3000 —— 会自动跳转到 `/zh`（默认语言）。

后台入口：http://localhost:3000/admin/login （需先完成下一步创建管理员账号）。

## 创建第一个超级管理员账号

后台账号使用 Supabase Auth 管理，`auth.users` 无法通过 SQL 种子文件直接写入，需要单独创建：

**方式一：通过 Supabase Dashboard（推荐，最简单）**

1. Dashboard → Authentication → Users → **Add user**，输入邮箱和初始密码，勾选 `Auto Confirm User`。
2. 复制新用户的 `UID`。
3. 打开 SQL Editor，执行（替换 `<UID>` 与邮箱）：

```sql
insert into public.admin\\\\\\\_users (id, email, full\\\\\\\_name, role\\\\\\\_id, is\\\\\\\_active)
values (
  '<UID>',
  'admin@ardaus.org',
  '系统管理员',
  (select id from public.roles where key = 'super\\\\\\\_admin'),
  true
);
```

4. 使用该邮箱和密码登录 http://your-domain/admin/login。

**方式二：登录后台后，用超级管理员账号在「管理员账号」页面创建更多账号**

首个超级管理员创建完成后，后续所有账号（内容管理员、会员管理员、分会管理员、只读查看）都可以直接在 `/admin/users` 页面创建，无需再手动操作数据库 —— 系统会自动完成 Supabase Auth 用户创建与角色绑定。

## 部署到生产环境（Vercel + Supabase）

1. 将代码推送到 GitHub / GitLab 仓库。
2. 在 [Vercel](https://vercel.com) 中 **Import Project**，选择该仓库。
3. 在 Vercel 项目的 **Settings → Environment Variables** 中配置与 `.env.local` 相同的变量（`NEXT\\\\\\\_PUBLIC\\\\\\\_SUPABASE\\\\\\\_URL`、`NEXT\\\\\\\_PUBLIC\\\\\\\_SUPABASE\\\\\\\_ANON\\\\\\\_KEY`、`SUPABASE\\\\\\\_SERVICE\\\\\\\_ROLE\\\\\\\_KEY`、`NEXT\\\\\\\_PUBLIC\\\\\\\_SITE\\\\\\\_URL` 填写正式域名）。
4. 确认 Supabase 项目已执行完第 4、5 步的迁移与种子数据（生产环境使用与开发环境相同或独立的 Supabase 项目均可，建议生产使用独立项目）。
5. 点击 Deploy。Vercel 会自动识别 Next.js 项目并使用默认构建命令 `next build`。
6. 部署完成后，重复「创建第一个超级管理员账号」章节的步骤，在生产 Supabase 项目中创建正式管理员账号。

### 关于 Supabase Storage 存储桶

`0011\\\\\\\_storage\\\\\\\_buckets.sql` 迁移会自动创建 5 个存储桶（`avatars` 头像、`logos` 合作伙伴 Logo、`media` 图片/视频、`downloads` 下载资料、`applications` 入会申请附件），并配置好公开读取 / 管理员写入的访问策略。无需在 Dashboard 中手动创建。

## 绑定自定义域名

1. Vercel 项目 → Settings → Domains → 添加域名（如 `www.ardaus.org`）。
2. 按 Vercel 提示，在域名注册商处添加对应的 CNAME / A 记录。
3. 生效后，回到环境变量将 `NEXT\\\\\\\_PUBLIC\\\\\\\_SITE\\\\\\\_URL` 更新为正式域名并重新部署（用于 sitemap、Open Graph、`robots.txt` 等正确生成绝对地址）。

## 数据备份与恢复

Supabase 项目本身提供：

* **自动每日备份**（Pro 及以上套餐，Dashboard → Database → Backups 中可查看与恢复）。
* **手动导出**：Dashboard → Database → Backups → 或使用 `supabase db dump` 命令随时导出完整 SQL 备份，建议在每次重大内容变更（如换届、批量导入会员）前手动导出一份留存。
* **Storage 文件**：头像、Logo、图片、下载资料均存放在 Supabase Storage，可在 Dashboard → Storage 中按桶下载备份。

恢复时，将备份 SQL 文件在新的（或清空的）Supabase 项目中执行即可还原全部数据结构与内容。

## 日常运营：非技术人员如何更新网站内容

登录 `/admin` 后，左侧菜单对应不同内容模块，操作方式统一：**列表页可搜索、新建、编辑、删除、上下移动排序；编辑页填表单、点保存即可，无需接触代码。**

|想做什么|去哪里操作|
|-|-|
|更换协会 Logo、首页大图、联系方式、首页统计数字|「站点设置」→ 选择对应设置项（如 `home\\\\\\\_hero`、`contact\\\\\\\_info`）编辑 JSON 内容|
|新增/修改领导人、理事、顾问信息（含头像、职务、简介）|「人员管理」→ 新建或点击「编辑」；未确定人选可勾选「职位待定 (TBA)」|
|发布一条新闻|「新闻管理」→「新建」，填写中英文标题/正文（正文为富文本编辑器，可插图、加粗、加链接），选择「状态」为「已发布」即可，也可先存为「草稿」|
|发布/更新一场活动|「活动管理」→「新建」，填写时间地点等信息，活动结束后可在「活动回顾」中补充图文总结|
|更新委员会/分会简介、负责人|「委员会管理」/「分会管理」→ 编辑对应条目|
|新增合作伙伴 Logo|「合作伙伴」→「新建」，上传 Logo（点击「上传」按钮直接从电脑选择图片，无需先获取链接）|
|修改「关于我们」「法律政策」等固定页面文字|「页面管理」→ 找到对应页面（按 slug 或标题搜索）→ 编辑正文|
|调整顶部/页脚导航菜单文字或顺序|「导航菜单」→ 编辑对应菜单项，或用列表页的上下箭头调整顺序|
|上传报告/政策文件供下载|「资料下载」→「新建」，上传文件后设置「公开」或「仅会员可见」|
|查看/处理网站联系表单留言|「联系与咨询」，可标记「跟进中/已处理」|
|查看会员/赞助捐赠意向|「捐赠与赞助意向」|
|审核入会申请|「会员申请管理」，可搜索/筛选/批量修改状态/导出 Excel/CSV，批准后可一键「转为正式会员」|
|管理正式会员是否公开展示|「正式会员」→ 编辑 →「对外公开展示」开关（默认关闭，需协会主动决定后再公开）|

所有图片类字段（头像、Logo、封面图）都提供「上传」按钮，直接从电脑选择文件上传至 Supabase 存储空间并自动填入链接，不需要额外的图床或技术操作。

## 角色与权限说明

|角色|说明|主要权限|
|-|-|-|
|超级管理员 Super Admin|全部权限，唯一可管理后台账号的角色|全部|
|内容管理员 Content Admin|负责日常内容更新|新闻/活动/委员会/分会/领导人/合作伙伴/页面/资料/导航/站点设置的增删改|
|会员管理员 Membership Admin|负责会员相关业务|审核/导出/删除入会申请、管理正式会员、查看捐赠赞助意向|
|分会管理员 Chapter Admin|仅能管理本人被指派的**单个分会**|编辑本分会的新闻/活动/自身分会资料、审核申请（数据库行级安全策略强制限定范围，即使前端出现问题也无法越权）|
|只读查看 Viewer|仅可查看操作日志|无编辑权限|

权限判定同时在两处生效（纵深防御）：应用层（页面跳转与按钮显隐）与数据库层（Postgres 行级安全策略 RLS）。即使应用层代码存在疏漏，数据库层策略仍会阻止越权的增删改操作。

## 项目结构

```
app/
  \\\\\\\[locale]/            公开门户页面（/zh、/en 前缀），按栏目分目录
  admin/
    login/             后台登录页
    (protected)/       登录后的后台页面（Dashboard、内容管理、会员申请、系统设置…）
  api/admin/           数据导出等需要文件下载响应的接口
  robots.ts / sitemap.ts   SEO
lib/
  supabase/            三种 Supabase 客户端（浏览器端 / 服务端会话 / 服务角色特权）
  data/                公开门户的数据读取层（只读已发布内容）
  admin/                后台专用：实体注册表（entityRegistry）、权限判定、仪表盘数据、导航配置
  actions/             全部 Server Actions（表单提交、内容增删改、审核流程）
  validation/          Zod 校验 schema
  i18n/                 双语路由与界面文案字典
components/
  site/                公开门户组件（导航、页脚、卡片、区块）
  admin/                后台组件（通用内容表单/表格、富文本编辑器、图表、审核面板）
  ui/                  跨前后台复用的基础组件
supabase/
  migrations/          0001\\\\\\\~0011 号数据库迁移（表结构、RLS 策略、存储桶）
  seed.sql             初始种子数据
docs/                  Phase 1 阶段产出的信息架构 / 数据库设计 / 设计规范文档
```

### 「通用内容管理」架构说明

新闻、活动、委员会、分会、领导人、合作伙伴、页面、资料下载、导航菜单这 9 类内容共用同一套后台页面（`app/admin/(protected)/content/\\\\\\\[entity]/...`）与同一套 Server Action（`lib/actions/admin-entities.ts`），差异完全由 `lib/admin/entityRegistry.ts` 中的字段声明驱动。**未来如需新增一种内容类型，只需要在该文件追加一份配置，无需新建页面或组件文件**，这也是满足「不能因为项目规模大就省略某个模块」这一要求的具体实现方式。

## 安全说明

* 后台所有页面与 Server Action 均校验登录状态与角色权限（`lib/auth/admin.ts`），并在 Postgres 行级安全策略中重复校验一次。
* `SUPABASE\\\\\\\_SERVICE\\\\\\\_ROLE\\\\\\\_KEY` 仅在 `lib/supabase/admin.ts`（标记 `import "server-only"`）中使用，且仅用于审计日志写入与管理员账号创建两处高权限操作，从不返回给浏览器或前台 API。
* 会员申请的手机号、邮箱、内部备注、审核意见等敏感字段**不会**出现在任何公开 API 或页面中；正式会员是否公开展示默认关闭。
* 所有公开表单（入会申请、联系我们、活动报名、订阅、捐赠意向）均有服务端 Zod 校验与内存级限流；`CAPTCHA\\\\\\\_SECRET\\\\\\\_KEY` / `NEXT\\\\\\\_PUBLIC\\\\\\\_CAPTCHA\\\\\\\_SITE\\\\\\\_KEY` 为预留接入位（见下方「待完善」）。
* 删除操作（内容、申请、账号相关的破坏性操作）均需二次确认弹窗；管理员账号本身不支持硬删除，只能「停用」，避免误删导致审计日志外键丢失上下文。
* 每一次内容增删改、申请状态变更、账号创建/修改、数据导出，均写入 `audit\\\\\\\_logs` 表，可在「操作日志」中查询（该表仅允许服务端写入，普通管理员账号即使被盗也无法篡改或删除日志）。
